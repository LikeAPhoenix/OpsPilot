# 1. 背景（Why）

当前 `chat`、`knowledgeindex`、`aiopsplan` 三个工作流在运行期存在重复构建执行图或 Agent 的问题，导致每次请求都重复执行 `buildRunner`、`NewPlanner`、`NewExecutor`、`NewReplanner` 等高成本初始化逻辑。该行为既增加请求延迟，也让构建错误推迟到首个请求才暴露，不利于启动阶段发现问题。

# 2. 目标（What，必须可验证）

- [ ] 将 `chat`、`knowledgeindex`、`aiopsplan` 三个工作流改为启动时构建一次、运行时复用
- [ ] 将执行图或 Agent 的构建失败前移到 `bootstrap.New(...)` 启动装配阶段暴露
- [ ] 保持现有 HTTP 路由、业务入参、工具名和返回结构不变

# 3. 非目标（Explicitly Out of Scope）

- 不调整 `internal/application` 和 `internal/interfaces/http` 的业务语义
- 不改动模型、Milvus、Prometheus、MCP 的配置结构
- 不引入新的公共缓存抽象或生命周期管理组件

# 4. 使用场景 / 用户路径

1. 服务启动时，`internal/bootstrap/app.go` 装配模型、向量库、工具与工作流。
2. 创建 `chat`、`knowledgeindex`、`aiopsplan` 工作流时，立即完成执行图编译或 Agent 构建。
3. 如果任一工作流构建失败，`bootstrap.New(...)` 直接返回错误，服务启动失败。
4. 服务启动成功后，`/api/chat`、`/api/chat_stream`、`/api/upload`、`/api/ai_ops` 的运行路径仅执行工作流，不再重复构建执行器。

# 5. 功能需求清单（Checklist）

- [ ] `chat.NewWorkflow` 增加 `context.Context` 入参，并在构造阶段缓存已编译的 `compose.Runnable`
- [ ] `knowledgeindex.NewWorkflow` 增加 `context.Context` 入参，并在构造阶段缓存已编译的 `compose.Runnable`
- [ ] `aiopsplan.NewWorkflow` 增加 `context.Context` 入参，并在构造阶段缓存已构建的 `adk.ResumableAgent`
- [ ] `bootstrap.New(...)` 更新为传入 `ctx` 调用三个 `NewWorkflow`
- [ ] 运行路径中不再重复调用 `buildRunner` 或 `planexecute.New*`

# 6. 约束条件（非常关键）

- 技术约束：继续沿用 CloudWeGo Eino 当前能力，不自行改造第三方库执行模型
- 架构约束：保持 `bootstrap -> workflow -> application -> interfaces` 的层次边界
- 安全约束：不得将任何密钥、DSN、租户信息写入代码或文档
- 性能约束：优化目标聚焦消除重复编译和重复构建，轻量级 `adk.NewRunner` 不作为本次优化对象

# 7. 可修改 / 不可修改项

- ❌ 不可修改：HTTP 路由路径、对外接口入参、工具注册名称、配置字段名
- ✅ 可调整：工作流构造函数签名、内部字段、执行器缓存方式、启动时装配逻辑

# 8. 接口与数据约定（如适用）

- `chat.NewWorkflow(config Config)` 调整为 `chat.NewWorkflow(ctx context.Context, config Config)`
- `knowledgeindex.NewWorkflow(config Config)` 调整为 `knowledgeindex.NewWorkflow(ctx context.Context, config Config)`
- `aiopsplan.NewWorkflow(config Config)` 调整为 `aiopsplan.NewWorkflow(ctx context.Context, config Config)`
- 其余应用服务与 HTTP 层接口保持不变

# 9. 验收标准（Acceptance Criteria）

- 如果执行 `go test ./...`，则整个仓库编译通过
- 如果启动装配时工作流构建失败，则 `bootstrap.New(...)` 直接返回错误
- 如果对同一个工作流执行多次调用，则运行路径不再重复调用 `buildRunner`、`NewPlanner`、`NewExecutor`、`NewReplanner`
- 如果调用 `/api/chat`、`/api/chat_stream`、`/api/upload`、`/api/ai_ops`，则返回语义与改动前保持一致

# 10. 风险与已知不确定点

- 启动阶段会比此前多做一次执行器构建，启动成本会略有上移
- 该需求默认 Eino 编译后的 `compose.Runnable` 以及预构建的 `adk.ResumableAgent` 可以作为长生命周期依赖复用
- 若后续工作流需要按请求动态注入不同结构的工具集或图结构，则需重新评估“启动时预编译”边界

# 11. 非目标

- 不新增新的性能监控指标
- 不改动 `examples/*` 的调用方式
- 不优化 `adk.NewRunner` 的实例创建
