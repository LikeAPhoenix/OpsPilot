# 1. 背景（Why）

当前 AIOps 联调虽然可以通过 `examples/prometheusmock` 构造活跃告警，但日志工具仍依赖外部真实 MCP 日志服务。这样会导致本地测试链路不闭环，告警、知识文档和日志证据之间也难以保持稳定对应关系。因此需要在仓库内提供一个本地 MCP 日志模拟服务，用于替代真实腾讯云日志进行联调。

# 2. 目标（What，必须可验证）

- [ ] 提供一个独立可运行的本地 MCP 日志模拟服务，暴露 `query_logs` 工具
- [ ] 保证 `prometheusmock` 的场景数据、知识文档和日志模拟数据一一对应
- [ ] 主服务继续通过 `mcp.url` 连接该 MCP 服务，无需改动现有 HTTP API
- [ ] 日志查询接口不使用鉴权

# 3. 非目标（Explicitly Out of Scope）

- 不还原腾讯云日志 API 的完整字段和协议细节
- 不将 MCP 日志模拟服务嵌入 `cmd/server` 主进程
- 不改动 AIOps 对外 HTTP 路径、工具加载方式和应用层语义
- 不引入数据库、消息队列或额外第三方基础设施

# 4. 使用场景 / 用户路径

1. 开发者启动 `examples/prometheusmock` 和 `examples/mcplogmock`。
2. `configs/config.yaml` 中的 `prometheus.base_url` 与 `mcp.url` 指向本地 mock 服务。
3. 开发者执行 `go run ./examples/aiops` 或调用 `/api/ai_ops`。
4. AIOps 工作流先从 Prometheus mock 获取告警，再通过 MCP mock 获取对应日志证据，最后结合知识文档生成分析结果。

# 5. 功能需求清单（Checklist）

- [ ] 在 `examples/` 下新增独立示例程序 `mcplogmock`
- [ ] 在 `examples/internal/` 下新增共享场景数据包，统一维护告警和日志测试数据
- [ ] `prometheusmock` 改为复用共享场景数据，而不是维护独立 `scenarios.json`
- [ ] `mcplogmock` 提供 `query_logs` 工具，参数至少包含 `region`、`topic_id`、`query`、`start_time`、`end_time`
- [ ] 日志查询结果支持 `limit`，默认 20，最大 100
- [ ] 支持 `single`、`multiple`、`empty` 三种联调场景
- [ ] `single`、`multiple` 场景中的日志内容必须能支撑知识文档推荐的排查关键词
- [ ] 输出清晰的启动日志，提示 SSE 地址、默认场景和可用场景

# 6. 约束条件（非常关键）

- 技术约束：继续使用 Go 标准库和 `mark3labs/mcp-go`，不新增 Web 框架
- 架构约束：日志 mock 作为 `examples/` 联调程序存在，不下沉到 `internal/application` 或 `cmd/server`
- 数据约束：场景数据必须是单一来源，避免 Prometheus mock 与日志 mock 不一致
- 安全约束：不得写入真实密钥、真实租户信息或外部鉴权配置

# 7. 可修改 / 不可修改项

- ❌ 不可修改：`/api/ai_ops` 路径、主服务启动入口、现有 MCP client 装配方式
- ✅ 可调整：mock 场景结构、示例程序目录、配置默认地址、测试数据文案

# 8. 接口与数据约定（如适用）

- `examples/mcplogmock` 默认监听 `:19092`
- `configs/config.yaml` 中 `mcp.url` 默认指向 `http://127.0.0.1:19092/sse`
- `query_logs` 工具入参：
  - `region`
  - `topic_id`
  - `query`
  - `start_time`
  - `end_time`
  - `limit`（可选）
- 返回体至少包含：
  - `success`
  - `message`
  - `matched_count`
  - `truncated`
  - `logs`

# 9. 验收标准（Acceptance Criteria）

- 如果执行 `go run ./examples/mcplogmock`，则程序可以成功启动并监听 SSE 地址
- 如果主服务启动时 `mcp.url` 指向该 mock，则 `bootstrap.New(...)` 可以成功加载 `query_logs`
- 如果运行 `single` 场景，则 AIOps 能查到“接口失败率过高”对应的日志证据
- 如果运行 `multiple` 场景，则 AIOps 能查到“服务下线”和“发现服务地域与资源地域不匹配”对应的日志证据
- 如果使用错误的 `region`、`topic_id` 或时间范围，则 `query_logs` 返回空结果或明确错误
- 如果执行 `go test ./...`，则整个仓库编译通过

# 10. 风险与已知不确定点

- 当前 AIOps 对日志工具的调用参数由模型决定，mock 只能通过工具 schema 和样例数据提高稳定性，不能完全控制模型行为
- `query_internal_docs` 当前是语义检索，不是标题精确匹配，因此告警名和知识文档标题必须尽量贴近
- mock 数据是联调样例，不代表真实线上日志量级和字段完备度

# 11. 非目标

- 不提供日志 Web UI
- 不支持动态写入、编辑或上传新日志场景
- 不增加日志鉴权、中间件或访问控制
