# 前端智能工作台界面重构与 AIOps 视图沉淀的实现总结

## 1. 实现了什么

本次开发完全推翻了粗糙的试验性前端，重新基于原生 JS 开发并由 Vite 构建代理服务。主要构建了一套符合 Glassmorphism（玻璃拟态）现代化审美的、深色模式友好的系统页面。在核心功能层，成功对接了原后端的所有主流能力：包括 JWT 会话认证与本地缓存治理、纯原生 `Fetch` 加持下的 SSE（Server-Sent Events）大模型流式对话打印解析体验，以及支持以长生命周期的专属只读会话承载 AIOps 告警综合分析日志。

## 2. 与需求的对应关系

*   **界面解耦与原生部署（对接需求项 2，5）**：彻底移除了庞大又低效的单页前端挂载方案代码堆填区，分离出清晰的 `api.js`，`auth.js`，`chat.js` 和 `aiops.js`。代码的结构做到了严格的前后端分离配置（代理分发）。
*   **流式长连接稳健性（对接需求项 5，9，10）**：手写了极简、精炼但支持跳包处理的 SSE 迭代解码器，完美解决服务端首帧附带 `event: connected` (JSON 探针) 被误入正文及空串断字消失导致的格式崩塌问题。
*   **AIOps 视图的深层梳理（对接需求项 2，4，5，9）**：废除了占据 DOM 巨大开支逻辑闭塞的全屏磨砂 `Modal`，借用完善的局部组件状态树，用一个专门置为 `isAIOps: true` 标记的 `LocalStorage` 会话记录取代弹窗，使用户可翻阅之前的 AIOps 排兵布阵；且在查看该报告时通过 `input-container` 直接隐藏切断了底层的不合法追问窗口，有效隔离了不同的推理维度机制。

## 3. 关键实现点

1.  **Axios 全局拦截**：利用拦截器针对 `/api` 前缀注入 Bearer Token，通过捕捉 `401 Unauthorized` 事件来主动清除非法 Cookie / Token 并跳转。针对特殊的长逻辑耗时请求 `/api/ai_ops` ，将 Axios 的 Timeout 从常见的 30s 扩张至 300s，避免 Agent 分析耗时时被前端硬性断开。
2.  **`ChatApp` 单例应用控制流**：在 `chat.js` 内以类对象形式实例化维护 `currentMode`，`chatHistories`，`currentSessionMessages` 等多个状态；并在切换路由及刷新页面时，巧妙利用原生 `window.history.replaceState` 配合 `URLSearchParams` 实现对 `session_id` 查询参数的修改。
3.  **SSE 的自定义数据收集与重组**：后端的片段往往并不以标准换行回传，在循环 `reader.read()` 时，采用按照 `\n` 切断尾块压栈的方案处理断流拼装，同时主动剥离非法空事件的异常堆积。

## 4. 已知限制或待改进点

1. **AIOps 报告不支持持久存入后端数据库**：由于当前后端架构对 Session 的实体只包含 `User Message `和 `AI Message` 的对话存储轮次逻辑设计，大篇幅的 AIOps 结论只能依赖本地浏览器 (`localStorage`) 长期存放，如果在另一台机器登录 OpsPilot，将没有 AIOps 分析报告的过往履历。
2. **文本输入框尚未拓展多级富文本互动支持（大文件）**：虽然已提供小文件（Markdown / Text）自动预处理导入 Milvus 图谱的快捷键，但在 UI 层面无法针对更繁杂且体积庞大的静态资产做深度的可视化流或大块渲染。未来可以追加通过 React 或 Vue 的重度组件封装。
