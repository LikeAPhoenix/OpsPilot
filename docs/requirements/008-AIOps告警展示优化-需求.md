# 1. 背景（Why）

在上一个版本完成前端重构并将 AIOps 搬出 Modal 变更为只读会话后，其实际视觉展示出现了明显瑕疵。主要问题有两个：一是主结论文本被套在序列化的 JSON `{"response": "..."}` 代码块之中，用户难以直接提取干货结论；二是底层思考和执行细节的长文本直接铺满页面，导致页面冗余，并且引发了过长的单行日志文本破坏外层聊天容器最大宽度限制排版的问题，文字紧贴内容框等样式 Bug。急需进行一次细致的 Markdown 层排版改造。

# 2. 目标（What，必须可验证）

- [x] 解析脱壳：识别并尝试解析后端的返回 `result`，抽取纯正的 `response` 字段内容展示为主结论，抛弃原始 JSON 字符串包装。
- [x] 细节可折叠化：借助原生 HTML5 `<details>` 和 `<summary>` 特性将过程数组（`detail`）统一包装层级，隐藏其默认可视占用。
- [x] CSS 漏洞防范与修复：修复所有列表无内边距导致的排版“撞墙”现象，修复因长串不折行代码引发 Flexbox 盒子宽度失控无限拓宽的现象。

# 3. 非目标（Explicitly Out of Scope）

- 不对旧的前端 `SuperBizAgentFrontend` 中的沉重 DOM 节点挂接方案进行像素级复制粘贴，而是转为通过 Markdown 流构建。
- 不修改 AIOps 后端 API 返回的数据长结构和格式机制。

# 4. 使用场景 / 用户路径

1. 用户点击“AIOps 分析”按钮。
2. 数据就绪后，页面只出现一段干净且拥有漂亮标题（带 💡 标志）的总结段落。
3. 如果用户确实希望查验大模型的分析心智链路，可以点击下方高亮的“🧠 点击展开：大模型推盘思考与执行链路”。
4. 随之拉开手风琴折叠面板，暴露内部逐个步骤带有 ```text 外壳的纯文本推演状态，无论多长都不会引起页面结构变宽。

# 5. 功能需求清单（Checklist）

- [x] 实现 `aiops.js` 中的 `JSON.parse` 探测解包。
- [x] 在生成的 markdown string 中增加 `<details>` 与 `<summary>` 的组合字符串构建。
- [x] 修正 `chat.css`：为 `.markdown-body details pre` 特别补上完全断行策略（`white-space: pre-wrap`, `overflow-wrap: anywhere`）。
- [x] 修正 `chat.css`：为 `.markdown-body` 下属的列表 `ol`, `ul` 补充 24px 左侧内边距解决贴边 Bug，处理全局 `*` CSS reset 的遗留问题。

# 6. 约束条件（非常关键）

- 技术约束：不要编写复杂的 `addEventListener` 操作 DOM 折叠。应直接依靠 Markdown 底层库 `marked.js` 天然兼容 `<details>` 这一 HTML5 标签的机制产生。
- UI 约束：即使是在窄屏或者极端的巨量文本长度下，消息体宽度不得超出父容器设定的 80%。

# 7. 可修改 / 不可修改项

- ❌ 不可修改：`/api/ai_ops` 的后端响应核心结构。
- ✅ 可调整：前端 Markdown 拼接与生成的组合形式；`chat.css` 与排版样式。

# 8. 接口与数据约定（如适用）

- 返回值 `result` 一般包裹为一个 JSON string，格式如 `{"response": ...}`。
- 返回值 `detail` 是一个由后台模型运行工具堆栈吐出的粗略字符串 Array。

# 9. 验收标准（Acceptance Criteria）

- 如果后端数据是标准带 `response` 的 JSON str，则展示的总结中不得包含 `{ "response":` 等字典前缀尾缀。
- 如果点击手风琴展开，长串 JSON 日志在界面内不得使中间的黑色消息盒子超出设定的 80% 画幅宽限制，必须强制换行或者触发局部水平滚动而严禁破坏根元素的 Flex 宽度控制。

# 10. 风险与已知不确定点

- 虽然尝试 `JSON.parse` 脱出 `response` 层，但必须考虑到部分模型后端未命中 JSON 输出格式的状况（即 fallback 到普通 string）。必须配置完备的 try-catch，以便在解析失败时能够安全回滚渲染普通的字符串结构。 

# 11. 非目标

（同重构要求）明确不支持将这些步骤数据强行回放进 Chat 的后台记忆上下文之中，以保证大模型不会被庞杂的 Log Token 挤爆。
