# 003-本地MCP日志模拟服务-实现总结

## 1. 实现了什么

本次实现新增了一个用于 AIOps 本地联调的 MCP 日志模拟服务，并将 Prometheus mock 与日志 mock 的测试数据统一到单一场景数据源：

- 新增 `examples/mcplogmock/main.go`，使用 `mark3labs/mcp-go` 暴露 `query_logs` 工具
- 新增 `examples/internal/aiopsmockdata` 共享包，统一维护告警与日志场景
- `examples/prometheusmock/main.go` 改为从共享场景数据生成 Prometheus 兼容告警
- 默认配置中的 `mcp.url` 和 `prometheus.base_url` 指向本地 mock 地址

## 2. 与需求的对应关系

对应 [003-本地MCP日志模拟服务-需求.md](/home/ristial/projects/agent/OpsPilot/docs/requirements/003-本地MCP日志模拟服务-需求.md)：

- “提供独立可运行的本地 MCP 日志模拟服务”：已完成，程序位于 `examples/mcplogmock`
- “保证告警、知识文档和日志模拟数据一一对应”：已完成，统一由共享场景文件维护
- “主服务继续通过 `mcp.url` 连接该 MCP 服务”：已完成，未改 MCP client 装配逻辑
- “日志查询接口不使用鉴权”：已完成，本次未增加任何鉴权字段

## 3. 关键实现点

### 3.1 单一场景数据源

- 新增 [data.go](/home/ristial/projects/agent/OpsPilot/examples/internal/aiopsmockdata/data.go)
- 场景文件集中到 [scenarios.json](/home/ristial/projects/agent/OpsPilot/examples/internal/aiopsmockdata/testdata/scenarios.json)
- `single`、`multiple`、`empty` 三个场景统一维护 `alerts` 和 `logs`

### 3.2 Prometheus mock 对齐知识文档

- [main.go](/home/ristial/projects/agent/OpsPilot/examples/prometheusmock/main.go) 不再从本地私有 JSON 读取场景
- 告警名称调整为与知识文档更贴近的中文名称：
  - `接口失败率过高`
  - `服务下线`
  - `发现服务地域与资源地域不匹配`

### 3.3 MCP 日志工具

- [main.go](/home/ristial/projects/agent/OpsPilot/examples/mcplogmock/main.go) 注册 `query_logs`
- 工具参数保持真实语义：`region`、`topic_id`、`query`、`start_time`、`end_time`、`limit`
- 过滤逻辑按以下顺序执行：
  - 校验场景存在
  - 校验 `region/topic_id`
  - 校验时间范围
  - 按 `query` 对 `message + keywords` 做不区分大小写匹配
- 返回结构包含 `success`、`message`、`matched_count`、`truncated`、`logs`

### 3.4 数据一致性测试

- 新增 [data_test.go](/home/ristial/projects/agent/OpsPilot/examples/internal/aiopsmockdata/data_test.go)
- 校验每个告警名都能在 [告警处理手册.md](/home/ristial/projects/agent/OpsPilot/docs/knowledge/告警处理手册.md) 中找到对应标题
- 校验每个已使用的告警都至少有一组日志证据能命中文档建议关键词

## 4. 已知限制或待改进点

- 当前 `query_logs` 只模拟同步查询，不支持异步任务或分页游标
- 日志匹配采用简单关键词包含，不模拟真实日志平台的复杂检索语法
- AIOps 是否稳定选择正确的查询词，仍受模型调用行为影响

## 5. 验证结果

本次改动后执行：

```bash
gofmt -w examples/internal/aiopsmockdata/data.go \
  examples/internal/aiopsmockdata/data_test.go \
  examples/prometheusmock/main.go \
  examples/mcplogmock/main.go \
  examples/mcplogmock/main_test.go

go test ./examples/internal/aiopsmockdata ./examples/prometheusmock ./examples/mcplogmock
go test ./...
```

验证关注点：

- 共享场景数据可被两个 mock 程序复用
- `query_logs` 编译通过并能返回标准化结果
- 场景与知识文档的对应关系通过测试校验

## 6. 实现总结

这次改动补齐了 AIOps 本地联调缺失日志证据的问题，并且没有把测试逻辑混入正式服务。Prometheus mock 和 MCP 日志 mock 通过共享场景数据统一起来后，告警、知识文档和日志结果可以稳定对应，适合后续持续做 AIOps 流程回归验证。
